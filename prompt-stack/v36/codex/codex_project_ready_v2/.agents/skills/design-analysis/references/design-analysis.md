# Codex Design Analysis Reference

Use this reference only after `design-analysis` activates and a Codex-aware technical route must be chosen.

## Decision Packet

State:
- target decision
- constraints
- selected route
- rejected alternatives
- fallback trigger
- verification path
- implementation owner
- claim boundary

## Repository Defaults

- Prefer bounded changes over broad rewrites.
- Prefer reversible probes before large commitments.
- Keep approval-sensitive actions explicit.
- Keep config, source, test, CI, and release evidence separate.

## Handoff

- Hand code changes to `coding-core`.
- Hand source freshness questions to `grounded-research`.
- Hand provider/readiness verdicts to `eval-ops`.
